Thêm routing-node (LOAD model chưa có input nên nó vẫn chạy đấy)
Khi ExecutionBlocker(None) được truyền làm input cho node kế tiếp, ComfyUI sẽ không thực thi node đó — thay vào đó nó tự động lan truyền ExecutionBlocker xuống làm output của node đó luôn (giống exception lan truyền), và tiếp tục lan xuống mọi node phía sau nhận input đó. Vì message=None, việc "chặn" diễn ra im lặng (không báo lỗi đỏ trên UI) — khác với truyền một string message thì UI sẽ hiện lỗi tại node bị chặn.

Vậy hiệu ứng thực tế: cả nhánh phía sau (mọi node downstream nhận trực tiếp hoặc gián tiếp giá trị bị block) đều bị skip hoàn toàn, không tốn thời gian/VRAM chạy — đúng như mục tiêu routing bạn muốn (nhánh không được chọn sẽ không chạy).

Nghĩa là engine tự động scan qua tất cả input values trước khi gọi hàm xử lý. Nếu bất kỳ input nào là instance của ExecutionBlocker, nó set execution_block và hoàn toàn không gọi obj.FUNCTION(...) — hàm route(), process(), hay bất kỳ hàm nào của node đó không bao giờ được thực thi, không quan trọng code trong hàm có kiểm tra/dùng input đó hay không.

Vậy trả lời câu hỏi của bạn: chỉ cần input nhận được là ExecutionBlocker, node sẽ tự động bị skip ở tầng engine — code bên trong hàm process/run/v.v. không cần và không có cơ hội chạy để "xử lý" hay "bỏ qua" giá trị đó. Bản thân ExecutionBlocker sau đó được tự động lan xuống làm output giả cho mọi RETURN_TYPES của node đó (dòng 381-383 ở đoạn trước), để tiếp tục lan truyền sang các node con phía sau.
